## Known Limitations

Stated plainly, matching the disclosure already present throughout `docs/ARCHITECTURE.md` and `ai-engine/README.md` — nothing here is claimed as done when it isn't:

- **No trained ML model.** Classification uses a rule-based strategy (`RuleBasedClassificationStrategy`), deliberately built behind a `ClassificationStrategy` interface so a trained model could be substituted later without touching the engine.
- **No live backend domain API.** Only `GET /api/v1/health` exists. The dashboard reads static JSON fixtures (`frontend/public/data/*.json`) generated by the ai-engine's `dashboard_export` stage, not a live backend endpoint.
- **No real-time/streaming ingestion.** Every phase, including the "streaming" benchmark in Phase 8, runs as an offline batch CLI job against files on disk — `StreamProcessor.process_event` is architecturally streaming-ready but nothing feeds it a live event source today.
- **No production deployment.** Docker Compose runs the stack locally only. The frontend container runs Vite's development server, not a production static build. No TLS, no secrets manager, no cloud infrastructure.
- **Limited real concept-drift history.** The delivered Phase 3 profile store was built from two runs against the same underlying dataset, so most entities show `drift_score ≈ 0.0` — Phase 8's concept-drift evaluator reports this honestly rather than fabricating a drift trend that isn't in the real data.
- **No formal Python linter/formatter configured.** `ruff`/`black`/`mypy` are not wired into `ai-engine`/`backend` as a committed config or CI step; a manual `ruff check` audit was run during Phase 8A polish (see below) but nothing enforces this on future changes.
- **No frontend ESLint.** `npm run lint` currently only runs `tsc --noEmit` (type-checking); no style/quality linter (ESLint) is configured.
- **Two confirmed-dead frontend files**, left in place with this disclosure rather than silently deleted: `frontend/src/components/system/BackendStatusCard.tsx` (superseded by `SystemHealthPanel.tsx`) and `frontend/src/components/ui/Progress.tsx` (scaffolded, never wired to a consumer). Safe to remove in a follow-up commit.

## Future Improvements

Realistic, not aspirational — matching `README.md`'s own Roadmap section:

- Wire a formal linter/formatter (`ruff`, `black` for Python; ESLint for TypeScript) into `.github/workflows/ci.yml` so future changes are gated, not just manually audited once
- Build real backend domain endpoints (alerts, entities, analytics) backed by the database, replacing the static-fixture frontend data path
- Train and integrate an ML-based classification strategy behind the existing `ClassificationStrategy` interface
- Add a production frontend build (static assets served by nginx or similar) as an alternative to the current dev-server Docker image
- Remove the two confirmed-dead frontend files once their absence is independently verified in a future review pass
